1. **Installation and diagnosis.** Save work and use the supplied authenticated
   installer with ordinary OS approval; do not remove recovery files. On Windows,
   Recovery should identify machine/account findings separately and explain known
   or unknown activity, package health and any next step without mentor clearance.
   When safe, Run validation should produce actual check results. PASS or FAIL
   must not acknowledge the interruption, claim the earlier operation succeeded
   or remove its evidence. If activity blocks Validation, record that finding.
2. **Acknowledge once.** If offered, choose Acknowledge interruption at startup, or
   deliberately request Install/Update/Repair first and use Acknowledge and continue.
   There must be no extra acknowledgment elevation or separate report/save click.
   Expect an automatic saved-summary reference, or an explicit save warning with
   the original evidence retained. No pending request means return to Overview
   without starting a change. A pending request returns to its normal review;
   ordinary mutation authorization still applies. Cancel rather than provisioning
   tools unnecessarily. Active/unknown activity or known damage may still block.
3. **Persistence and status.** Close/reopen SDE normally. If guidance calls for a
   normal Restart, save work, restart and Check Again; a legacy record may need a
   further Restart after its first baseline is captured. The same acknowledgment
   should persist, not silently replay a requested operation. Overview should
   reuse the existing first Ready! card: current blockers/warnings have a reason,
   and the old acknowledged incident does not alone keep it in attention state.
   Yellow for unverified package health is allowed and must explain that reason.
4. **Reports/history and safe UI review.** Recovery remains accessible. Review the
   saved summary and optionally export a shareable HTML copy; Cancel in the chooser
   must not claim a save. Summaries may identify the device: inspect before sharing.
   Detailed logs are optional/off by default; nothing uploads automatically.
   Retained history/report deletion is optional, explicitly confirmed and only
   removes that account's view/report, not minimum decisions/current evidence.
   A diagnostic ambiguous/unavailable row may correctly offer no deletion action.
5. **Healthy Mint and controls.** Preserve the accepted tools/environment. Check
   the normal Overview, accessible Recovery/history, and Install preflight without
   provisioning. Buttons should be **Continue with Install**, **Check Again**,
   **Cancel**, with Continue primary. Cancel must start no changes. Check the theme,
