Responsive rules

Reading order
Status → reason → observation time → single action → supporting counts.
Keyboard
Page headings receive focus after navigation; focus never moves merely because status refreshes.
Announcements
Preflight completion, blockers, recovery results, and report-save outcome use bounded live-region messages.
Not color alone
Every green/yellow/red state includes a status word, icon, reason, and action.
Zoom and reflow
No horizontal page scrolling at supported zoom; action buttons remain at least 44 px high.
Reduced motion
No essential meaning depends on animation; loading text remains visible.
Technical detail
Student guidance uses common language. Exact platform subsystem evidence stays in details and reports.
Stale observations
Displayed timestamps and Refresh prevent old evidence from appearing current.

Recovery lifecycle

Operation starts→ crash/restart →Running?no →Interrupted→Validate→Resolve, recommend Repair, or mentor guidance

Preflight lifecycle

Fresh results→Known blocker?yes → stop · no →Unavailable?yes → one-attempt acknowledgment · no →Confirm operation

Prototype approval boundary

Approval fixes the screen hierarchy, primary wording, state taxonomy, and transitions shown here. Production implementation may refine spacing and platform-native file-picker details without changing the approved behavior.
